## 九月底：先看清病 不急着治 / Late September: Name the Illness First, Do Not Rush to Treat It

<!-- bilingual:section -->

<!-- lang:zh -->

9 月 17 日 我让 bot 对整个库做了一次只读诊断 什么都不改 只数数

约 5488 篇 md

根目录近四成几乎是空壳

未解析链接约八千

我盯着这两个数字看了很久

八千个悬空的链接 意味着我写过八千次「这里应该连到某个东西」

然后那个东西从来没有存在过

诊断的结论很刺耳 病在「收集伪装成思考」

同一天我定下四条底线 后面一个月所有动作都绕着它们转

- 遵守 [[file over app]] 笔记是文件 工具可以换
- 学徒的产出只进 AI outputs/ 不污染我自己写的部分
- flomo 的随想保持原子导入 不合并 不改写
- 属性跟着我自己的 Property 词汇表走 能不加就不加

<!-- lang:en -->

On September 17, I had the bot run a read-only diagnostic on the entire vault—changing nothing, just counting

About 5488 md files

Nearly 40% of the root directory was almost an empty shell

About eight thousand unresolved links

I stared at these two numbers for a long time

Eight thousand dangling links meant I had written 'this should link to something' eight thousand times

And then that thing never existed

The diagnostic conclusion was harsh: the sickness lies in 'collecting disguised as thinking'

On the same day, I set four bottom lines, and all actions over the following month revolved around them

- Adhere to [[file over app]]: notes are files, tools can be changed
- Outputs from the Apprentice only go into AI outputs/, without polluting the parts I wrote myself
- Keep thoughts from flomo atomically imported: no merging, no rewriting
- Properties strictly follow my own Property vocabulary—if an addition can be avoided, don't add it

The diagnosis only clearly named the condition, without altering any structure

What I did most in October was cutting back

On October 14, I established a rule called the 'Iron Law of Content'

Never force writing on anything not personally experienced; keep thinking, doing, and signing on separate tracks

External drafts can only keep things I have actually done; what hasn't been done must never be written as done

This rule later directly governed things over on the Obsidian side

Compiling articles, drafting tutorial materials, or writing external introductions must all pass this gate first

Around October 21, I put a stop to two things

The first was the bidirectional link pack from Dan Koe and Dontbesilent

I originally planned to batch import them, only to discover that what came in were hollow summary shells, with bidirectional links stripped down to plain text

Paused immediately

The second was the daily linking report for personal notes

It ran every day and produced output every day, but the more I looked at it, the more it felt like spinning its wheels

Scrapped entirely

On the same day, I wrote the 'Obsidian Apprentice Behavioral Constraints'; the strictest line was: Clippings must be usable body text, and stripping concepts down into mere keywords is forbidden

On November 4 and 5, I used canvas to sort through the skills and routines

In-vault reporting uniformly uses obsidian:// links

Dedicated bots each handle their own area—who writes to Obsidian, who writes to flomo, and who schedules—no longer mixed in a single session

On November 6, I tackled six things all at once

First: Renaming and division of labor

The original Obsidian Apprentice was renamed Jackywine Digital Garden

flomo as RAM, local Obsidian as the hard drive

RAM holds fleeting thoughts, tweets, and short links; tracing back to the source needs to be fast

The hard drive stores full-text clippings, [[wikilink]], MOC, and long articles; they need to be preserved

Tweet ingestion is still handled by a dedicated flomo bot, with collisions coordinated by the main dispatcher

Second, walk through the setup process as a new user

From how to address me, which step flomo is connected up to, and the vault path, all the way to folder conventions and guardrails

Four guardrails were set on the spot: private fleeting thoughts like moods, anxiety, and voice journals are strictly skipped; ask first before batch modifications/deletions or batch moves; no unauthorized publishing or deployment; keep only firsthand experiences in external drafts

My feeling after running through it was very direct: setup is simply putting 'where I allow you to touch' into words that the next session can also read

<!-- lang:en -->

Third, get Obsidian CLI working

I hit a small snag at this step

Under /Applications/Obsidian.app/Contents/MacOS/, there are two very similar things

One is the GUI Obsidian, and the other is the real command-line obsidian-cli

macOS file names are case-insensitive by default; calling the wrong one will hang directly

I symlinked obsidian-cli to ~/bin/obsidian; that directory was already in my PATH, so there was no need to touch /usr/local/bin, which requires admin privileges

After getting it connected, I did a quick spot check: about 174 tags, 13 backlinks to [[1ndex]], 17 backlinks to [[file over app]], and the interlinks between hubs are all still there

What used to require scanning files across the entire vault now takes just a single command

I also added 'prioritize using the CLI and minimize full vault scans after setup' to the setup skill to save tokens

Fourth, do another checkup

Still read-only, no changes

About 5661 md files, 173 more than on September 17

Unresolved links dropped from about eight thousand to 4747, down by nearly half

About 4139 files in the root directory, of which short stubs under 50 bytes account for about one-third, or roughly 43% by 'hollow shell feel'

This proportion has barely budged compared to late September

Broken links are decreasing, but short stubs aren't

Over the past month, I spent a lot of effort making the links look healthy

Yet that pile of stubs of a few dozen bytes lying in the root directory is what collecting disguised as thinking really is

Links can be fixed with tools; if thoughts aren't written down, tools can't fix them

The health check concluded with three recommendations: Don't tackle unresolved links first; only sample and manually process short stubs; clean up dirty links by pattern; strictly forbid batch-creating empty shell pages to fill gaps.

It was finally packaged into the evergreen-note skill.

I wrote the note [【Note Titles Should Be APIs]] a long time ago, but it wasn't until this day that it was truly formalized into a template.

## 这一个月留下来的规矩 / The Rules That Survived This Month

<!-- bilingual:section -->

<!-- lang:zh -->

翻完一个多月的记录 能留下来的就五条

双层先想清楚再写

闪念和推文进 flomo 长文和概念网进 Obsidian

不让 bot 擅自把一条闪念扩成长文

串库必须给理由

related-notes 找出来的每一条都要写清楚为什么现在该一起看

只会复述我刚写过的话 那这个 bot 就可以关了

Ask first

批量删 批量加链 发布 部署 没点头不动

Skill 比再描述一遍值钱

以前换个会话就要重教一遍笔记格式

写成 skill 之后 换 bot 换会话 边界都还在

展示站要留数据口

做数字花园相关站点的时候 条目不写死在 UI 组件里

只改 content.json 让 bot 和人都只动数据

<!-- lang:en -->

Looking through over a month of records, only five rules survived.

Think through the two layers before writing

Fleeting thoughts and tweets go into flomo; long-form writing and concept networks go into Obsidian.

Don't let the bot expand a fleeting thought into a long article without permission.

Cross-linking across the vault must come with a reason

Every single note pulled up by related-notes must clearly explain why they should be viewed together right now.

If it only restates what I just wrote, then this bot can be shut down.

Ask first

Batch deleting, batch linking, publishing, deploying—don't touch anything without approval.

A skill is worth more than describing it all over again.

In the past, switching to a new session meant reteaching the note format all over again.

Once written into a skill, the boundaries remain intact even when switching bots or sessions.

Showcase sites should leave a data interface

When building digital garden sites, don't hardcode entries into UI components.

Only modify content.json, letting both the bot and humans touch only the data.
