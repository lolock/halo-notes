写完一篇文章，最磨人的往往是配图：图库里挑不出对的，AI 生成的又一眼假——文字乱、风格飘，十张里能用的不到三张。你把骰子重掷了一遍又一遍，最后在废片堆里捡一张「还算能看」的，安慰自己「AI 嘛」。

我现在的日常是另一番样子：写完文章，说一句「配图」，AI 按我的规矩自己出图——字体是我的字体，配色是我的配色，别人一眼认得出这是我文章的图。

中间隔着的，就是一个自己的作图 skill——一份教 AI 按你的品味干活的说明书。大神的作图工具大多长这样，而且很多已经开源，装上就能用。直接用，是完全正当的选择——我自己的作图 skill，就是从拿别人的开源 skill 开始的。

但用着用着，会有两层不满足浮上来。第一层：它不知道你嫌什么。字体不是你的字体，配色不是你的配色，人物更不是你的人物——那是别人的品味。第二层更微妙：大家都在用同一款，你的封面和一万个人的封面，长着同一张脸。

人总想要点自己的小特色。这不矫情，这就是「拥有」的原始动机。

我的判断是：拥有一个自己的作图 skill，起点不是从零写一个，而是拿大神的骨架，喂自己的翻车。 而且写好它和改它——包括改别人的——是同一件事的两半。底层只有一句话：问题从来不在模型，在它的 skill 里没有你。模型决定出图的下限，你的约束才决定稳定性。

为了把这件事讲透，我把自己用了三个月、更新日志里记了七个版本的作图 skill（wtt-nine-comic-imagegen，当前 v2.2.3）整个拆开：它从哪来的、里面到底有什么、哪几行最值钱、怎么改别人的、怎么修自己的。拆到最后，给你一条今晚就能开工的路径，和一份按症状查的排错清单。

![原文插图](/halo-notes/articles/assets/x-2098840772804268248/inline-05.jpg)

先说清楚：这不是又一篇《Skill 从入门到精通》。系统教程已经够多了，缺的是把一个真实在用的 skill 当众拆开——包括它被打脸的部分。

### 先看一次现场

## 一、来历：这个 skill 不是从零写出来的

先交代来源，因为它直接推翻一个误区：拥有自己的 skill，第一步不是打开空白文档。

我的作图 skill 有五种风格，其中三个，起点都是别人。

封面那个风格（极简线条人），来自一次「拿来」：我看到「有机大橘子」开源的橙线插画 skill——把长文观点转成纽约客式的极简插图，画面干净、留白讲究，一眼喜欢。开源了，就拿来用。但真正让它变成「我的」的，是后来的三层改造——原版的线是橙色，橘子的橙；我换成克莱因蓝；字体换成「喜脉喜欢体」；人物 IP 整个换成现在这个方框眼镜的线条小人。怎么动的手，第五节细说。

![原文插图](/halo-notes/articles/assets/x-2098840772804268248/inline-16.jpg)

漫画那个风格（恶搞科普长图）也是：看到混子曰的漫画特别有意思——就是那个后来更名「混知」、用「半小时漫画」把艰深知识画成段子的公众号——我去研究它的逻辑，拿过来结合我对文案的想法，慢慢改成了现在这个「用菜市场解释数据库」的九号漫画。

![原文插图](/halo-notes/articles/assets/x-2098840772804268248/inline-07.jpg)

生活感人像同样如此：看到一组很有生活感的摄影提示词，拿过来，按我自己的场景和光线习惯，改成了现在的十二个变量池。

但「拿来」只是第一天。真正的拥有，发生在之后的三个月翻车里。

六月中旬，我要给一批技术概念配恶搞科普长图，用的就是从混子曰逻辑改出来的那一版。拿来的时候觉得挺完整，一跑真实任务就开始翻车，而且翻车的花样远比想象的多。

第一批废片里，有三种死法最典型。

第一种，比喻死。要画「API」，我写了「餐厅菜单」——概念完全正确，模型也老老实实画了，但那张图没人会笑。后来我才想明白：餐厅菜单和 API 一样体面、一样严肃，中间没有降维的落差。恶搞科普的命是反差，概念对但不好笑，等于死。

第二种，构图死。人物动不动画到半屏高，手绘批注和主题物件被挤到角落，长图变成了人物头像图。我明明写了「人物要小」。

第三种，质感死。最气人的一种。我要求手绘风，模型给我手绘的人物，但批注文字是工工整整的宋体——人是对的，字是打印的，整个画面瞬间从漫画变成 PPT。

每翻一次车，我就把修复办法写回一个 markdown 文件。记账本之外还有一个关键进化：我给恶搞长图的主角立了几道 pass/fail 测试——辨识度过不过、风格一致不一致、表情够不够夸张，每条都是可以判「过」或「不过」的题。这一步把「感觉不对」翻译成了「测试不过」，主观印象从此有了客观抓手。

写到第 N 条，它已经是一个 skill 了。回头看更新日志，三个月里的七个版本是这样来的：

![原文插图](/halo-notes/articles/assets/x-2098840772804268248/inline-14.png)

这张表是全文的第一个结论：七个版本，没有一个是「灵感升级」，全是「翻车修复」。skill 不是写出来的，是修出来的。 而修的原材料，是一次一次具体的、有日期的翻车。

把它和来源故事合在一起，公式就完整了：骨架可以是别人的，翻车必须是自己的。 只拿不修，skill 还是别人的；只修不拿，你会在别人已经踩过的坑里再摔一遍。大部分人写不好 skill，恰好两头都做反了——骨架靠自己硬憋，翻车从来不记录。

我在自己的知识库里记过一个外部印证（转述自一篇爆款 Skill 作者的万字复盘，大意如此）：他的 PPT skill 起因也不是「想做 skill」，是真的要做一场分享；第一版成型后，用五六轮对话一轮轮调间距、字号、配图；讲完发现观众最关心的不是分享内容，而是 PPT 怎么做的——副产品变成了主产品。路径和我的完全同构：真实需求，先做一次，然后一轮轮修。

这条路径就是 skill 的生命周期：发现真实需求 → 做一次高质量产物 → 把翻车抽象成约束 → 工程化 → 测试 → 收集反馈。大部分人卡在哪？卡在第一步之前——没有真实需求，只有「别人都在做 skill，我是不是也该有一个」。没有需求，就没有第一批废图；没有废图，后面几步全是空中楼阁。

## 二、拆开看：这个 skill 里到底有什么

先盘点家底：五种视觉风格，一个 263 行的 SKILL.md，十六个参考文件，两张参考图。

五种风格是五种完全不同的视觉人格：恶搞科普竖版长图（手绘黑白、荒诞表情、无分镜边框）、手绘卡通信息图（横版 16:9、关键词突出）、Q 版四格漫画（可爱分格、温暖治愈）、极简线条人（细黑墨线、纯白留白、克莱因蓝点缀）、生活感人像（vibe 摄影质感、十张成组）。

![原文插图](/halo-notes/articles/assets/x-2098840772804268248/inline-12.jpg)

### 五种模式速览

前面的线条人和 9 号漫画已经是 D、A 的样片；下面补上另外三种。它们的外形不同，但共同点都是把你的判断写成可复用的规则。

B｜手绘卡通信息图：把结构讲清。

![原文插图](/halo-notes/articles/assets/x-2098840772804268248/inline-01.jpg)

C｜Q 版四格漫画：把过程讲出来。

![原文插图](/halo-notes/articles/assets/x-2098840772804268248/inline-09.jpg)

E｜生活感人像：把真实感留住。

![原文插图](/halo-notes/articles/assets/x-2098840772804268248/inline-10.jpg)

但行数和文件数不值得拆，值得拆的是分层。把全部内容摊开，它们其实压在三层上：

### 第一层：交付层——触发词，skill 的门牌

SKILL.md 开头的 description，写的不是「我有什么功能」，是「什么时候该加载我」。比如「9号漫画」「恶搞科普」「竖版长图」「那个搞笑的竖图」，每种风格一组中英文触发短语，按风格分组。

这是新人最容易写错的地方：把 description 写成功能介绍。「本 skill 支持多种风格、内置强大的模板库」——这类话不会让 AI 在对的时候想起你。用户会说出口的原话，才是触发词。 有人会说「那个搞笑的竖图」，但没人会说「强大的模板库」。

### 第二层：工程层——骨架、变量池、速查表

中间那层是可复用的结构：每种风格一个提示词骨架（填空即用的模板）、一张比例速查表、一个变量池。

比例这条值得单独说。我的速查表里写死了五种风格各自的像素——恶搞长图 720x2800、信息图 1920x1080、四格漫画 1080x1440、生活感人像 1080x1440 或 1080x1350。为什么写这么死？因为「竖版长图」四个字对模型是模糊的，它经常给你一个接近正方形的东西；「约 720x2800 竖版长图」是精确的。比例必须「具体像素 + 方向描述」双锚定，两个一起写，模型才知道上下界在哪。

变量池的思路在生活感人像风格里最完整：表情、服装、场景、瞬间状态、景别、焦段、机位、构图、前景、光线、色彩、摄影状态——十二个变量，每个池子预备至少六个取值，每次生成从池子里抽值组合。后面会讲到，这个池子还承担着防同质化的功能。

信息图的骨架里还有一套信息分层规则：一张图的内容拆成四层——标题、核心论点、细节、装饰，核心信息点不超过五个到七个。这也是约束：画面塞多少东西是有数的，超过这个数，信息图就变成信息垃圾场。 人读图的处理带宽是固定的，品味的一部分就是替读者守住这条带宽。

### 第三层：经验层——铁律、负面清单、比喻成败目录

最贵的一层。风格铁律、主体一致性控制、N1-N7 负面提示框架、比喻成败目录，全在这里。

「风格铁律」每种风格自成一套，全是品味的私产：恶搞长图的铁律是「用最俗的东西解释最玄的——菜市场、厕所、泡面、相亲」；信息图的铁律是「所有元素必须手绘，禁止照片、3D、写实」；四格漫画的头身比锁死在 2:1 到 3:1，三角色分工（好奇者、活泼者、引导者）可换皮不可换骨。这些不是通用设计原则，是我一个风格一个风格喂出来的。

「主体一致性控制」是跨风格的一条硬规则，共四条，管的是「十张图要像同一个人画的」这件事：锚点描述永远写在提示词开头；参考图必须上传——参考图不是可选附件，是锚点本身；多页生成时复用同一段角色锁定块（二十到四十字，逐字复制，不要每页重写）；首轮先出二到四个候选形象让用户挑，锁定后再批量。任何一条松了，人物就开始漂。

除了分层，这个 skill 里还有三个值得抄走的结构决策：

决策一：锚点与变量分离。 每种风格都先分清两件事——识别锚点（永远不变的：克莱因蓝、纯白背景、头身比）和可变变量（每次可调的：比喻方案、场景、文案）。不分这个，skill 要么僵死（每次生成一模一样），要么失忆（每次生成完全不同）。

决策二：共享机制抽取。 凡是跨两个以上风格重复出现的经验，抽到一个独立文件，编号成 N1 到 N7，各风格用编号引用。理由很实际：同一条经验写三遍，改的时候就会漏改两遍。同样的道理我用在了输出层——四格漫画的「视觉风格指令块」规定只输出一次，作为独立代码块，后面每一页只用一行引用它，不许重复全文。重复不只是冗余，重复是版本分裂的温床。

决策三：删自己写的字，比写字难。 v2.1.0 那次重构，SKILL.md 从 1009 行砍到 263 行，砍掉 74%。剃刀只有一句话：这一句删掉，AI 会不会做错？不会，就删。 显而易见的内容在白白消耗上下文，只留下会改变模型行为的判断。砍完还要在文件末尾加一段「加载指引」——告诉 AI 什么时候去读哪个参考文件。skill 不是写得越全越好，是要让对的规则在对的时候被读到。

## 三、底牌：最值钱的不是「要什么」，是「不许什么」

现在拆到底牌。整个 skill 里，我认为真正构成壁垒的，几乎全是「不许」清单。

### 一个被打脸的实验：字体词失灵事件

七月的 v1.1.1 版本，记录了一次实测：线条人风格的金句文字，我写过「无衬线字体」，模型照样给打印体；改成「手绘字体」，还是打印体。字体分类词对图像模型基本无效——它不知道你脑子里的「手绘感」长什么样。

最后的解法是把描述换成物理动作：「钢笔手写，字迹歪斜，大小不一，笔触顿挫，像便签上随手写的」。这才管用。这条规则后来固化成了 skill 里的一条通用机制，原文长这样：

```markdown
# skill 原文：文字/字体渲染通用规则（节选）
句式统一：写「用{笔}手写，{特征1}，{特征2}，{特征3}，严禁{字体分类词}」
- 钢笔 / 马克笔手写
- 字迹歪斜、大小不一
- 笔触顿挫、像便签随手写的
- 严禁打印体 / 电脑字体 / 宋体 / 黑体 / 等线体 / PPT 字体
```

左边一列是无效的字体分类词，右边一列是生效的物理动作——注意每一句「特征」都是模型能直接执行的动作，没有一个词在描述「风格」。

这次翻车给我的教训比修复本身值钱：模型听得懂动作，听不懂审美。 你说「文艺一点」「高级感」「性冷淡风」，模型其实没收到任何信息。你的品味必须先翻译成模型可执行的东西。

![原文插图](/halo-notes/articles/assets/x-2098840772804268248/inline-06.jpg)

### 品味翻译的三种形态

翻译成数字。 「人物要小」没用，「人物占画面 1/12 到 1/10」有用；「多点留白」没用，「留白 ≥40%」有用；「金句短一点」没用，「中文 ≤6 字」有用——这是实测出来的边界，超 6 字乱码和拆字几乎必然，超 8 字几乎必败。

翻译成动作。 就是字体事件：钢笔、马克笔、字迹歪斜、大小不一。

翻译成禁止。 「蓝色点缀」会得到一百种蓝，写死色号「唯一点缀色克莱因蓝 #002FA7」就只有一种。眼镜也一样：光写「方框眼镜」远远不够，模型会给你圆框、墨镜、护目镜、加粗美式框……所以我的 skill 里这条是枚举禁止变体的：不要圆框、不要椭圆、不要菱形、不要墨镜、不要护目镜、不要镜腿、不要鼻梁——至少列六个变体。

精确到什么程度算够？看 skill 里这条眼镜铁律的原文：

```markdown
# skill 原文：风格 D·眼镜铁律（节选）
- 眼镜（身份标识，必须保留）：两个方框镜片 + 一根短横线贴着两镜片
上缘连成一体——这根横线是镜框的上边梁，属于眼镜，不是眉毛，共三笔
- 镜片高度约为头部圆的 1/4，宽度约为高度的 1.2 倍；两镜片间距约等于
一个镜片宽；上边梁贴着镜片上缘，长度约等于两镜片宽度之和
- 全头除眼镜三笔外没有其他笔画：不要眉毛、不要抬头纹、不要在眼镜上
方再加任何线条
- 不要画镜框加粗、不要透明镜片、不要墨镜、不要护目镜、不要美式粗框
- 不要画鼻梁、不要画镜腿、不要画细线眼镜、不要画无框半框
```

听起来变态，但每一次「差不多就行」，模型都会替你差出更多——它不产出你要的精确，只产出你描述的精确。

### N1-N7：负面提示框架

把所有「不许」归拢起来，skill 里沉淀了七条通用机制，做成一张速查表：

![原文插图](/halo-notes/articles/assets/x-2098840772804268248/inline-08.png)

其中两条最反直觉。N1 的「写两遍」听起来像玄学，它是行为观察——负面约束在长提示词里的留存时间，比你想象的短。N4 是大多数人共同的盲区：比喻目录里记着一类典型的渲染失败——「人物一脸严肃地站在荒诞场景里，喜剧效果全毁」，修复就是显式写「表情夸张滑稽，嘴巴张大，眼睛瞪圆」。你以为「荒诞场景」四个字已经把喜剧感说清了，模型不知道「夸张」要到什么程度，就给你一张中性脸。

一句话总结这张表：正向要求，模型基本都知道；负面边界，才是你的专家经验。

### 比喻成败目录：品味最生动的部分

skill 里有个我很喜欢的文件，叫比喻实战目录——专门记录哪些比喻成功、哪些失败。它把「品味」这个词拆成了三层。

第一层是想法品味。成功的比喻：系统架构 = 合租房马桶堵了谁来通；技术债务 = 借高利贷装修，每个月还利息比工资多；缓存 = 冰箱里常备可乐，省得每次跑超市。失败的比喻：API = 餐厅菜单；A/B 测试 = 考试的选择题。

「餐厅菜单」这个比喻值得多说两句。它是经典比喻，概念映射完全正确——但它错了：没人会笑。它太体面、太接近专业场景，没有降维的落差。同一个 API，能成立的方向是「你妈让你去隔壁借酱油，邻居大妈说只借不还罚五十块，每次最多借 200 毫升」。「概念对」和「效果好」之间隔着的那道缝，就是想法品味。 它写不进任何教程，因为它高度依赖你对「好笑」和「合适」的私人判断。

第二层是表达品味。想法有了，怎么把它组织进提示词——先说什么后说什么、锚点放哪、约束放哪，这是结构手艺。

第三层是渲染品味，也就是比喻目录里的第三类记录：「比喻对但画面出问题」。人物太大、边框把漫画切成 PPT、手写批注变宋体、画面挤到没有留白、配色跑出渐变和阴影。想法和表达都对，最后死在渲染层——这类失败最冤，也最少有人记录。

skill 能做的是把这三层判断的结果都存下来——下次直接绕开「餐厅菜单」，人物开头就写小，批注开头就写手写动作。它把你踩过的坑和做过的好决定，变成下一次生成时的默认值。

顺带一提，这件事还有复利：平台会换，模型会换代，工具会过时，而你沉淀下来的那套约束清单——你对比例、字体、配色、比喻的判断——会跟着你走，越攒越厚。

### 顺手收一条：反馈来了怎么接

和负面清单配套的，还有一条微观循环：用户反馈「不对」的时候，不要推倒重写方向，把反馈翻译成更强的约束，放进下一版提示词的开头。标题不对 → 开头写「顶部标题必须写 XXX，不要写 XXX」；太像某品牌 → 开头写「原创内容，不复制任何品牌名、logo、角色」；画面太空泛 → 加行业物件和主题道具。反馈的本质是缺约束，重写的本质是浪费上一版。

## 四、比喻：写提示词之前，先把产品想明白

负面清单管的是「不许坏」，但一张概念图真正的好坏，先取决于画面在说什么。线条人风格的工作流里，写提示词之前有一个必做步骤：设计比喻。这一步有个前提判断，我写在了 skill 里：比喻是产品，渲染只是执行。

五条设计原则，条条都是踩坑换的。

![原文插图](/halo-notes/articles/assets/x-2098840772804268248/inline-04.jpg)

先找张力。 好的概念图表达一组相反——多 vs 一、空 vs 暖、生成 vs 判断。画面说什么，先在内容里找到那个张力，找不到张力就不要动笔。

动作场景优先于抽象符号。 「一个人递一杯热茶」好过「一个漂浮的对话框」；「一个线条人踩空一级台阶」好过「一排门里有一只奇异的把手」。判据只有一句：如果比喻需要解释，它就失败了。

一图一意。 如果画面需要两句话才能讲清楚，砍掉一半。

点缀色要刻意放置。 克莱因蓝落在哪个元素上，回答的是「这张图在讲什么」——那扇被保留下来的窗，那杯热茶，那根连贯的线。乱撒点缀色，等于没有点缀色。

放大尺度差。 物件画得宏大，人画得极小。一个小人面对一堵巨大的墙，失衡感本身就是内容。

版式也是同理。恶搞长图有六种版式骨架（标准、对照、路线、解剖、黑板、剧场），信息图有五种（流程、对比、层级、时间线、数据）。骨架都是预先验证过的库存——AI 不需要从零发明版式，它只需要选一个对的，把内容填进去。让 AI 自由发挥，它大概率给你平庸；给一副验证过的骨架，它才有机会接近你的品味。

这五条原则加上骨架库存，构成了 skill 的另一半：负面清单保证不坏，比喻设计才保证有可能好。

## 五、改造：改别人的，改自己的

写完第一版，真正的功课才开始。改这个动作有两种对象：改别人的（拿来改造），改自己的（用中修复）。先说改别人的——它是我整个 skill 的起点，也是你上手最快的一条路。

### 改别人的：我拿大橘子的 skill 动的三刀

拿别人的 skill，最忌讳的是一上来就大改。动刀之前先做一件事：原样跑几次——你得先知道它本来什么样，才知道你的每一刀带来了什么。然后三层往下改，每层动一类东西，改完一层测一次。

第一刀，调参数。只动配置类的东西：比例、色号、数量。原版的点缀是橙色的线——橘子的橙；我换成克莱因蓝 #002FA7，全图只留这一种蓝。连颜色都换成自己的，这是最直接的宣示主权。这类改动风险最低、见效最快，适合建立手感。

第二刀，改描述。原 skill 的文字描述是别人的语感，我把画面文字全部锁定成「喜脉喜欢体」的手写风格——这部分怎么改才管用，等讲到字形参考图那一节细说。

第三刀，换 IP。人物是 skill 的灵魂，也是你最该换成自己的部分。我把角色定义整个重写：新的头部规则、新的方框眼镜、新的身体完整性标准，配上新的判断测试。这一刀改完，别人已经认不出它从哪来了。

三刀之外还有一件别忘的事：看一眼开源协议，尊重原作者。 拿，要拿得干净。

![原文插图](/halo-notes/articles/assets/x-2098840772804268248/inline-13.jpg)

接下来的问题更真实：改完之后呢？改完之后，它就是你的了——以及，它开始翻车，而且是用你的方式翻车。以下三个，都是我自己修出来的。

### 火柴人事件（v2.2.1）

九月初，线条人开始被画成火柴人：一个圆脑袋，加一条腿。排查发现是身体描述那句「极简的单弧躯干」有歧义——模型按它的理解极简，把躯干极简没了。

修复分两步：先把身体定义重写到不可歧义，再补一张完整性测试表。修复后的 skill 原文长这样：

```markdown
# skill 原文：风格 D·身体定义与完整性测试（v2.2.1 修复后）
- 身体：躯干必须是一根清晰可见、连续不断的黑色弧线：上端直接连接头
部圆的底部，经颈部向下延伸至腰胯；躯干长度至少等于一个头部直径，
不可省略或缩成一点。不是线框、不是双线、不是体块
- 完整性硬约束：全身从头顶到双脚完整入镜——两条手臂连接躯干中上部、
末端各有简笔手；两条腿从腰胯分叉、末端各有脚；躯干和四肢不得被遮
挡、裁切或与背景线重合
# 完整性测试（pass / fail）
- 通过：头底→连续躯干→腰胯连接清楚，两臂两腿与手脚齐全
- 失败：躯干缺失或缩成一点、悬浮头、四肢断开、道具遮身、裁掉手脚
```

这次改造动的是判断结构，不是某个词——改完了还要同步中英文模板、示例和反馈规则。一个地方改漏了，下个月就会在另一个场景再翻一次车。

### 字形参考图（v2.2.2）

上面说的改字体，解法在这一版落地。物理动作词已经把文字稳定性救回来大半，但「歪斜」「顿挫」这种词依然隔着一层描述——每个人的歪斜不一样。解法是存了一张「喜脉喜欢体」的字形参考图进 skill 的 assets，生成含字图片时随提示词一并提供：只参考字形，不复制样张的文案和排版。

这次改造给我的启发是：当描述词到头了，就给模型看实物。 语言的天花板，图片能顶破。

### 六字之变（v2.2.3）

「中文 ≤6 字」原本是铁律。但封面场景来了：文章封面必须放完整标题，标题不可能六个字。

规则被新场景推翻，改法是划适用域：非封面的画面文字维持 ≤6 字；封面标题按语义换行、按需调整字号，完整性优先，不再套六字限制，并补上「标题逐字校对、按实际发布比例检查裁切」两条新约束。

顺带记录这次改动的真实成本：改一条封面规则，同步了中英文两套模板、示例和反馈规则，共四处。如果没有决策二的共享机制抽取，这个数字会是十处——而且我一定漏掉三处。skill 的结构决定了它改起来的成本，这是写第一版时就要还的债。

这次给我的提醒是：规则不是圣旨，场景变了规则就得改。 一条从来没有失效过的规则，未必是对的，可能只是新场景还没来。

### 改造的三个层次

上面三次是修 bug，还有一次是修结构——v2.1.0 把 SKILL.md 从 1009 行砍到 263 行的那次大瘦身，第二节讲过了，不重复。把这几次改造归拢一下，改一个 skill 其实只有三个层次，难度递增：

![原文插图](/halo-notes/articles/assets/x-2098840772804268248/inline-15.png)

配套的纪律来自改造五步——定位、理解、修改、测试、迭代。定位是找到要改的位置，理解是改之前先搞懂「它原来是干什么的」，这两步最容易被跳过，也最不该被跳过。然后是修改和测试。提炼成四条纪律：每次只改一处；改完必测；一次不对很正常，多轮调整是常态；改动超过一半，别改了，直接重做。 「每次只改一处」尤其重要——你一次改三处，测出问题时永远不知道是哪句在起作用，你的失败记录也就废了。

最后补一个全局视角。把七版更新日志连起来看，其实就是一条循环：真实需求 → 先做一次 → 把翻车抽象成约束 → 工程化 → 测试 → 收集反馈 → 下一版。skill 的生命周期不是八步走完的流程图，是这个循环转起来的过程。所以别指望一步到位——80 分先用，边用边修，我的 v1 到 v2 就是这么滚出来的。

## 六、生成观：skill 管下限，你管挑选

结构讲完了，改造讲完了，还剩一个更上层的东西——你和 skill 之间怎么分工。skill 里写了一句生成哲学：抽奖，不是质检。 并行生成多个候选，全部展示，不预筛选，人从候选里挑。为什么这么设计？一句话：生成是廉价的，AI 自检是昂贵的且价值有限，人的品味才是质量关卡。宁可多生成两个让用户选，也不要花同样的时间让 AI 自我审查。

这个哲学还有两个配套动作。其一，「差一点但不对」的时候，在选中的候选基础上微调，不要推倒重来——你放弃的不是一张废图，是一次已经跑到八成的迭代。其二，分块确认：四格漫画那种多页任务，先出封面和第一页锁视觉方向，确认后再批量；每三到五页暂停一次。别让 AI 一口气跑完一个你还没确认过方向的任务。

![原文插图](/halo-notes/articles/assets/x-2098840772804268248/inline-11.jpg)

顺便说一个容易被忽略的细节：提示词本身也有品味。生活感人像风格的提示词要求「自然融合为 80-150 字的一段中文，不要结构化罗列」——同样十二个变量，写成参数表，出图机器味十足；按八步公式融成一段人话（机位焦段开头，场景主体居中，光线前景收尾），画面才有生活摄影的呼吸感。给模型的输入若是一张表格，就别指望输出有温度。 你怎么写提示词，就是在用什么口吻跟模型描述世界。

把抽奖哲学推到底，连「多样性」都要写成约束。生活感人像风格一次出十张，怎么保证不是一个模子？我把多样性写成了硬规则：景别至少三种、焦段至少四种、室内外各至少三张、光线至少四种、服装至少六种、相邻两张共用变量不超过六个。不写这些，十张图就是同一张图的十次滤镜。

约束也负责尊重用户的意志。这个风格还预设了四种锁定模式：用户说「十张全要夜景」，光线变量整列锁死；说「就要坐在咖啡馆的」，场景字段锁定、其余照常抽值；只给一张参考图说「照这个感觉」，就整体风格锁定。skill 的约束是默认值，不是铁笼子——用户指定了什么，什么优先。

但这里有一条必须划清的边界：约束保护下限，审美决定上限。 skill 的作用是让你的图从「偶尔能看」变成「基本都能看」；至于那张让你愿意拿去当封面的图，依然靠你在候选里挑中的那一眼。skill 替不了你挑，它只保证你有得挑。

## 七、你今晚就能拥有：从改一个别人的 skill 开始

拥有之后的日子，比「出一张好图」要长。我常用的几种图——封面、信息图、漫画、人像——都收在同一个作图 skill 里：写完一篇 markdown 文章，插图、封面一张话说清；插完图，还能接着让它干别的。skill 用久了会开始组合：组合起来之后，它就不只是一个作图工具，而是你工作流的一段。

要走到这一步，把「改别人」和「写自己」两条路拧成一条，四步，今晚就能开工。

第一步：找一个你喜欢的开源 skill，先原样用几次。 别上来就改。用它跑三五个真实任务，记下每一次的别扭——字体不像我、颜色太素、人物不是我。记现象，别急着记原因：「文字变成打印体」是现象，「模型不行」是结论。这些别扭就是你的改造清单，也是你品味的第一次显形。

第二步：三层往下改。 先调参数（色号、比例，风险最低），再改描述（字体、风格词——记得用物理动作词，别用字体分类词），最后换 IP（角色定义整个换成你的）。每次只改一处，改完测一次。

第三步：喂它翻车。 改造完不是终点，翻车才是原料。把每次翻车的现象翻译成约束——能定量的写数字，涉及质感的写动作，涉及审美的写禁止。举一条完整的翻译链，让你看这个动作有多具体——

翻车现象：手写批注变成了工整的宋体。第一反应的修复：「批注要手写风格」——没用，字体分类词。第二版修复：「批注用手绘字体」——还是没用。第三版，翻译成动作：「批注用钢笔手写，字迹歪斜可爱，大小不一」——生效。最后写进负面清单时再补两刀：字数压到 6 字以内，核心禁止项在开头约束区和排版区各写一遍。

从一张废图到一条生效的约束，这就是拥有作图 skill 的全部游戏。十张废图的价值，比十篇教程高——教程给的是别人的坑，废图给的是你的。每条写完过一遍剃刀：没有这句，AI 会不会做错？不会就删。第一版有三条高质量约束，好过三十条正确的废话。

![原文插图](/halo-notes/articles/assets/x-2098840772804268248/inline-17.jpg)

第四步：门牌换成你的。 触发词改成你自己会说出口的原话，失败记录表建起来。从这一天起，它和原作者的版本就是两个 skill——你的那本失败账，是它真正的出生证明。

两条工程纪律提前立好。其一，内容长了别硬塞：单图塞不下就拆页，多页任务先让 AI 出页面大纲，你确认了再逐页生成——大纲确认这一步省掉的是整批返工。其二，通用要求只写一次：视觉风格写成一个独立指令块，每一页引用它，不要每页复制全文——从第一天起就把版本分裂堵死。

一个可以照抄的最小模板：

三个预判提醒，都是常见摔点：

```markdown
---
name: 我的作图-skill
description: （写触发词，不写功能介绍）
用户说「封面图」「头图」「XX 风格」时使用。
---
# 风格定位
一句话：这是什么风格，给什么场景用。
# 铁律（不可变锚点）
- 比例：具体像素 + 方向（如 1080x1440 竖版）
- 配色：写死色号（如 唯一点缀色 #002FA7），不写「暖色调」
- 主体：锚点描述永远写在提示词开头
# 负面清单（来自我的翻车记录）
- 文字：严禁打印体，写「钢笔手写、字迹歪斜、大小不一」
- 中文文字 ≤6 字；核心元素禁止变体至少枚举 6 个
- （N1）核心禁止项在开头和排版区各写一次
# 失败记录
| 日期 | 翻车现象 | 新增约束 |
|------|----------|----------|
```

• 别写成使用说明书。 skill 是写给 AI 的约束，不是写给人的介绍。每句话都应该是在改变模型行为，不是在描述功能。

• 别追求一步到位。 80 分先用。我的七个版本里，前三个版本回头看都不堪入目，但没有它们就没有后面。

• 别贪快连改三处。 测出问题时你不知道是哪句在起作用——你的失败记录会开始撒谎。

## 八、排错章：按症状查

收藏这一节就够了。按症状组织，每条是一条排查链。

症状一：文字乱码、变印刷体。

查描述里是不是用了字体分类词 → 换成物理书写动作词（钢笔手写、字迹歪斜）→ 查字数是否超 6 字 → 超了就拆短，或留白走后期叠加 → 稳定性要求极高就上字形参考图。

症状二：多张图不像同一个角色。

查锚点描述是否写在提示词开头 → 是否上传了参考图 → 多张图是否复用同一段角色锁定块（20-40 字，逐字复制，不要每张重写）→ 还不行，首轮生成 2-4 个候选形象，锁定一个再批量。

症状三：十张图长得一样。

查变量池是否够大（每个池至少 6 个取值）→ 是否写了差异下限（景别、焦段、光线各至少几种）→ 相邻两张共用变量是否超过 6 个。

症状四：改了 A，坏了 B。

查是否一次改了多处 → 回滚，恢复成只改一处 → 用边界样本重测 → 检查改提示词时是否漏改了对应的禁止变体列表和中英文双语模板。

症状五：skill 不被触发。

查 description 是不是写成了功能介绍 → 换成用户会说出口的原话 → 补中英双语变体 → 触发词之间用分号分隔、按风格分组。

症状六：画面太挤、像 PPT。

查是否漏了留白约束 → 写「段间距是正常行距的 2 倍，场景之间至少留白一个人物高度」→ 查边框：写了「不要矩形边框」吗 → 记得按 N1 写两遍。

症状七：人物像某个明星。

查是否描述了具体公众人物特征 → 加一句「不画成任何具体公众人物的相似脸」——这条不只是风格问题，是肖像权问题。

症状八：画面空泛、没信息量。

先分清两种「空」：没内容，还是内容太多挤成一团。前者查有没有给行业物件和主题道具——空泛的修复是加具体的东西，不是加形容词；后者查信息点是不是超了五个到七个，超了就砍。

求助之前，先备齐三样现场：当时用的完整提示词、翻车的图、你上一轮的改法。三样齐了，问题基本自己就浮出来了。

## 九、边界，以及今晚就能做的事

最后交代这套方法的适用边界，先劝退两种人。

如果你一个月才出一张图，别做 skill——记住两条约束（比例写具体像素、文字写物理动作）就够了，skill 的全部价值在重复，维护成本会吃掉收益。如果你的任务是纯探索性创意——没有明确的「对错」，约束会杀创意——跳过约束清单，只保留「先做一次，再加迭代」这半个循环。

再说写 skill 这件事本身对人的要求。它需要三种知识叠在同一个人身上：知道什么结果算好——这是你的专业判断；知道模型什么能做、什么做不稳、什么必须工程化兜底——这是你对 AI 上下限的手感；知道使用场景和使用门槛——这是产品思维。三者缺一，skill 就缺一角：只有专业知识，写出来是愿望清单；只有 AI 手感，写出来是技巧堆砌；只有产品思维，写出来是空壳。这也解释了为什么同一个模型、同一份教程，不同人写出的 skill 差距那么大——差距不在提示词功夫，在这三种知识的交集大小。

第三条边界最重要：skill 固化判断，但不产生判断。 它能把你对比例、字体、配色的判断变成默认值，能让这些判断在你不在场的时候依然生效——但它不能替你判断什么是好的。没有翻过车的手，抄来的清单也用不好，因为你不知道哪一条在救你。这也是为什么模板里的「失败记录」表我放在最后却没有让你抄——那一栏只能自己填。

还有一重回报很少有人提：skill 攒到一定程度，它自己会变成内容。你正在读的这篇文章就是证据——素材几乎全部来自那个 skill 自己的文件和更新日志，翻车记录变成了案例，设计决策变成了观点。第一节提到的那个外部案例走得更远：文章、开源仓库和 skill 互相喂养，skill 从生产力变成内容的矿。

回到开头的那个判断：出图不稳，不是模型不行，是它的 skill 里没有你。模型这一年还会更强，出图的下限还会更高——但「每次都像你」这件事，模型永远替你做不了，因为它不知道你嫌什么。

所以今晚就可以动手：翻出你最近的十张废图，写下三条「下次不许」。

那就是你作图 skill 的第一版。
