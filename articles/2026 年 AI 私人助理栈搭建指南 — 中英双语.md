问题在于，大多数助理都在等你打字。

有些只在你坐在聊天窗口前的时候才工作。

有些在压缩上下文或者交接之后就什么都忘了。

还有一些每次巡检都要开口，或者干脆一直挂成进程跑着。

结果都一样：你得到的是一个需要人盯着的聊天机器人，而不是私人助理。

你不需要更大的提示词，也不需要永不休息的模型。

你需要的是模型外面的一整套栈：每 30 分钟来一趟，除非真有要紧事，否则保持安静。

Anthropic 的《Building always-on agents》（作者 William Hu）把这个循环拆成五个部分：事件收件箱、定时器、记忆、权限、发件箱。我们给它们起的名字分别是托盘（Tray）、闹钟（Alarms）、笔记本（Notebook）、旋钮（Dial）、桌面（Desk）。

也就是说，你要搭的是：

- 一个托盘，每一次唤醒都落到这里，以及负责往里写的闹钟

- 一个笔记本，能熬过上下文压缩、交接和一整夜的睡眠，再加上一份交接笔记（Handoff Note）和一块铭牌（Nameplate）

- 一个旋钮、一张通行证（Hall Pass）和一张安静的桌面，决定它能做什么、你能听到什么

- 一次 30 分钟的巡检（Round），带沉默规则，以及一次夜间清扫（Night Sweep），把当天的日志变成当前状态

助理并不是一个「永远在线」的进程。Anthropic 说那句话描述的只是用户体验。agent 大部分时间在睡觉。事件就绪时开始一次运行，agent 干活，把发生的事存下来，然后回去睡。这个循环不断重复。

如果你想知道自己装的到底是什么、每一件东西为什么存在，就继续往下读。

<!-- lang:en -->

The problem is that most assistants wait for you to type.

Some only work while you sit in the chat.

Some forget everything after a compact or a handoff.

Others talk every time they check in, or stay running as a process.

The result is the same: a chatbot you have to babysit, not a personal assistant.

You do not need a bigger prompt, or a model that never sleeps.

You need a stack around the model that checks in every 30 minutes, and stays quiet unless something actually matters.

Anthropic's Building always-on agents, written by William Hu, calls the five parts of that loop an event inbox, timers, memory, permissions, and an outbox. Our names are the Tray, Alarms, the Notebook, the Dial, and the Desk.

That means building:

- a Tray where every wake-up lands, and Alarms that write it

- a Notebook that survives a compact, a handoff, and a night of sleep, plus a Handoff Note and a Nameplate

- a Dial, a Hall Pass, and a quiet Desk that decide what it may do and what you hear

- a 30 minute Round with a silence rule, and a Night Sweep that turns the day's log into current state

The assistant is not "always on" as a process. Anthropic says that phrase is just the user experience. The agent spends most of its time asleep. A run starts when an event is ready, the agent does the work, it saves what happened, and it goes back to sleep. The cycle repeats.

If you want to understand what you are installing and why each piece exists, keep reading.

## 一页讲清核心思路 / The idea in one page

<!-- bilingual:section -->

<!-- lang:zh -->

你要做的不是更大的提示词。

你要做的是一个薄薄的循环，外面围五个部分，然后教这个循环什么时候开口。

<!-- lang:en -->

You are not building a bigger prompt.

You are building a thin loop with five surrounding parts, then teaching that loop when to speak.

<!-- /bilingual:section -->

![一次运行的闭环：托盘有活就开跑，干完把结果交给桌面，然后回去睡；默认状态是睡觉](/halo-notes/articles/assets/x-2125281837673226340/fig2-five-parts.jpg)

<!-- bilingual:section -->

<!-- lang:zh -->

**1. 托盘（The Tray）。** 每一次唤醒都落在这个持久列表里：你发来的消息、一个 webhook、一个到点的闹钟、一次巡检。Anthropic 把它叫事件收件箱。不要让每个来源直接去调 agent。两个事件同时到，就会有两场运行互相抢；崩一次，事件可能就丢了。托盘是唯一的事实来源。同一时间只跑一个 worker。能等的时候，把待处理事件批量处理。

**2. 闹钟（Alarms）。** 后续事项和重复日程。到点的闹钟负责往托盘里写事件。
Anthropic 把它们叫定时器。助理靠这个东西才有主动性。
一次后续（follow-up）是 agent 给自己定的截止时间；一个日程（schedule）是周期性任务。
闹钟本身不会启动运行。调度器把到点的闹钟写进托盘，然后唤醒 worker。

**3. 笔记本（The Notebook）。** 那些能熬过上下文压缩、交接和一整夜睡眠的文件。
Anthropic 关于记忆的经验法则是：只存 agent 没法再查回来的东西。日历或 issue 追踪器里已经有的，存一个指针就行。
每次运行开始时加载一小撮文件：你的指令、你的笔记、最近的消息、任务进度。
会话太长时，压缩它，或者开一个新的，但先写一份交接笔记。这两种做法都会丢细节。

**4. 旋钮（The Dial）。** 决定助理什么时候行动、什么时候问、什么时候停的规则。这才是风险所在。
后台运行握着你的访问权，无人看管地干活。
对每一次工具调用，agent 应该继续、阻塞，或者等你批准。
密钥放在保险库里，只能随着一张通行证（Hall Pass）流动——一个有范围、会过期的句柄。真正的密钥始终待在保险库里。
Anthropic 描述的是放在 agent 环境之外的凭据代理。
等待是一次延迟的工具调用：运行结束、会话在调用中途被保存、你的回答以一条托盘事件回来，而 worker 在这期间可以干别的活。

**5. 桌面（The Desk）。** 一次运行结束时留下一条简短通知，或者什么都不说。
Anthropic 把它叫发件箱。后台工作不该把每一步的轨迹实时推给你。
一次运行只有三种结束方式：在桌面上留一条消息、判断没有什么需要发出、或者请求批准。
从安静开始。用时间换取注意力。

这五个部分还压在另外几个你要建的文件和任务上。

- 铭牌（The Nameplate）。助理是谁、你是谁，每次运行开始时加载。

- 交接笔记（The Handoff Note）。在上下文压缩或交接之前写好，写清悬空事项和精确 ID。

- 巡检（The Round）。每 30 分钟一次检查，把到点的闹钟写进托盘，并执行沉默规则：不需要你就写 NOTHING，有简短结果就写 UPDATE，需要你回答就写 NEEDS INPUT:。

- 夜间清扫（Night Sweep）。每晚把当天的日志变成当前状态的作业。

Serein 已经在 Mac 上实现了其中很大一部分：Relay 巡检、日程、目标、监视、webhook、审批卡片、钥匙串保险库和 SQLite 记忆。

插件文件夹是留给你还得自己归档的那部分，以及任何没跑在 Serein 里的 CLI agent 用的。

<!-- lang:en -->

**1. The Tray.** The durable list where every wake-up lands: a message from you, a webhook, a due Alarm, a check-in.
Anthropic calls this the event inbox. Do not let each source call the agent directly.
Two events at once start competing runs. A crash can lose an event.
The Tray is the source of truth. One worker at a time. Batch pending events when you can.

**2. Alarms.** Follow-ups and repeating schedules. A due Alarm writes the Tray.
Anthropic calls these timers. This is how the assistant becomes proactive.
A follow-up is a deadline the agent sets for itself. A schedule is a recurring task.
An Alarm does not start a run on its own. A scheduler fires what is due, writes an event to the Tray, and wakes the worker.

**3. The Notebook.** The files that survive a compact, a handoff, and a night of sleep.
Anthropic's memory rule of thumb: store only what the agent cannot look up again. If it already lives in a calendar or an issue tracker, save a pointer.
Load a small set of files at the start of every run: your instructions, your notes, recent messages, and task progress.
When a session gets too long, compact it or start a new one, but write a Handoff Note first. Both options lose detail.

**4. The Dial.** The rule for when the assistant acts, asks, or stops. This is the risk.
A background run holds your access and works unattended.
For each tool call, the agent should proceed, block, or wait for approval.
Secrets sit in a vault, and move only with a Hall Pass: a scoped, expiring handle. The real secret stays in the vault.
Anthropic describes a credential proxy outside the agent's environment.
The wait is a deferred tool call: the run ends, the session is saved mid-call, your answer comes back as a Tray event, and the worker can do other work in the meantime.

**5. The Desk.** Where a finished run leaves a short notice, or stays silent.
Anthropic calls this the outbox. Background work should not stream a step-by-step trace at you.
A run ends in one of three ways: a message on the Desk, a decision that nothing needs to be sent, or a request for approval.
Start quiet. Earn attention over time.

The five parts sit on a few more files and jobs you will build.

- The Nameplate. Who the assistant is and who you are, loaded at the start of every run.

- The Handoff Note. Written before a compact or a handoff, with open loops and exact IDs.

- The Round. The 30-minute check that fires due Alarms into the Tray and applies the silence rule: NOTHING if nothing needs you, UPDATE for a short outcome, NEEDS INPUT: if you must answer.

- Night Sweep. The nightly job that turns the day's log into current state.

Serein already implements a lot of this on the Mac: Relay check-ins, schedules, goals, watches, webhooks, approval cards, a Keychain vault, and SQLite memory.

The add-on folder is for the pieces you still have to file yourself, and for any CLI agent not running inside Serein.

### AGENTS.md

<!-- bilingual:section -->

<!-- lang:zh -->

这是 CLI agent 应该读的第一个文件。它是地图，不是百科。伴生文件夹里的这一份会告诉 agent 加载身份、当前状态和 recap，并在后台运行没什么可说的时候回复 NOTHING。

<!-- lang:en -->

This is the first file a CLI agent should read. It is a map, not an encyclopedia. The copy in the companion folder tells the agent to load identity, current state, and the recap, and to reply NOTHING when a background run has nothing to say.

- identity/SOUL.md
- identity/USER.md
- identity/AUTONOMY.md
- memory/current/STATE.md (if it exists)
- memory/working/RECAP.md (if you are resuming after a compact or a handoff)

- memory/hourly, memory/daily, memory/weekly: the coarsening timeline
- memory/progress: one file per open task (OPEN, DONE, NEXT)

1. Write a Handoff Note before you compact, or before you hand off to another harness.
2. Never print or copy values from secrets/keychain/. Issue a Hall Pass instead.
3. If nothing needs the user's attention, reply with exactly: NOTHING

### SOUL.md 与 USER.md / SOUL.md and USER.md

<!-- bilingual:section -->

<!-- lang:zh -->

这就是铭牌。链上每一个 harness 都会在每次运行开始时加载这些文件。它们对应 Anthropic 说的「用户指令」和「用户笔记」。用户不会总在旁边给你指方向，所以指令必须能延续下去。

两个文件里都不要放密钥。某个事实如果已经存在于别的系统，存一个指针就好。

<!-- lang:en -->

This is the Nameplate. Every harness in the chain loads these files at the start of every run. They map to Anthropic's "user instructions" and "user notes." The user will not always be around to steer, so the instructions have to carry over.

- Load SOUL.md, USER.md, AUTONOMY.md, and memory/current/STATE.md at the start of every run
- Write a recap before context is cut
- Never print values from the vault. Use a Hall Pass.

### AUTONOMY.md

<!-- bilingual:section -->

<!-- lang:zh -->

这个文件说明什么时候行动、什么时候问、什么时候停。在这份指南里，它绑到 Serein-Bot 的 docs/permissions-and-safety.md 那三个级别上。

付款在任何级别都留在你手上。在网站上点击、打字，以及在 Mac 应用里动手，默认都是关着的，直到你自己打开。

## 7) 通行证 / 7) The Hall Pass

<!-- bilingual:section -->

<!-- lang:zh -->

通行证是一个有范围、会过期的句柄。真正的密钥留在保险库里。不要把真实登录凭据从一个 agent 传给下一个。Anthropic 描述的是放在 agent 环境之外的凭据代理：agent 发出不带凭据的请求，代理在转发之前把真凭据注进去。

Serein 已经把密钥值存在 Mac 钥匙串里。插件脚本是一个你能自己跑、也能自己读的小范式。它不是 Serein SecretVault 的替代品。

<!-- lang:en -->

A Hall Pass is a scoped, expiring handle. The real secret stays in the vault. Do not pass real logins from one agent to the next. Anthropic describes a credential proxy outside the agent's environment. The agent sends a request without credentials. The proxy injects the real ones before forwarding.

## 8) 夜间清扫 / 8) Night Sweep

<!-- bilingual:section -->

<!-- lang:zh -->

夜间清扫是每晚把当天的日志变成当前状态的作业。Anthropic 给这件事起的名字是 dreaming：一个离线作业，回顾过去的会话、替换过期的条目，找出那些只在很多次运行里才会浮现的模式。已经公开的常驻助理拆解里描述过类似的作业：把当天的日志粗化，写一份当前状态文件。Rohan Adwankar 的 Muse 拆解里就提到一个 dreams/ 文件夹。

scripts/dream.py 是一个很小、确定性的版本。它不调模型。它读当天笔记、recap、progress 文件和今天的 outbox，然后写 memory/current/STATE.md，上一个状态保留成 STATE.prev.md。以后你可以把组装那一步换成一次模型调用。

1. 在 pa-guide-build 里跑：

<!-- lang:en -->

Night Sweep is the nightly job that turns the day's log into current state. Anthropic's name for this is dreaming: an offline job that reviews past sessions, replaces outdated entries, and finds patterns that only show up across many runs. Published teardowns of always-on assistants describe a similar job: coarsen the day's log and write a current-state file. Rohan Adwankar's Muse teardown mentions a dreams/ folder.

scripts/dream.py is a small, deterministic version. It does not call a model. It reads the daily note, the recap, progress files, and today's outbox, then writes memory/current/STATE.md. The previous state is kept as STATE.prev.md. You can later swap the assemble step for a model pass.

1. From pa-guide-build, run:

```bash
python3 scripts/dream.py
```

<!-- bilingual:section -->

<!-- lang:zh -->

我在巡检实验之后在机器上跑它，夜间清扫的状态记录下了当天桌面上的三行：1 个 NOTHING、1 个 UPDATE、1 个 NEEDS INPUT。它保留了每周报告那个悬空事项，并把下一次运行指向 recap 和当天笔记，而不是原始日志。

## 需要注意的地方 / What to watch out for

<!-- bilingual:section -->

<!-- lang:zh -->

两个地方同时唤醒（Two wake-ups at once）

- 问题：Serein Relay 和插件里的巡检同时触发，你会收到两份简报。

- 解法：无人值守的工作只留一个调度器，或者只对没跑在 Serein 里的 CLI agent 用插件。

<!-- lang:en -->

Two wake-ups at once

- Problem: Serein Relay and the add-on Round both fire, and you get two briefs.

- Solution: Pick one scheduler for unattended work, or run the add-on only for CLI agents that are not inside Serein.

<!-- /bilingual:section -->

<!-- bilingual:section -->

<!-- lang:zh -->

clone URL 里的拼写错误（A typo in the clone URL）

- 问题：Serein-Bot 的 README 和从源码构建的文档都让你 clone codejunkie99/SereinBot，那个 URL 会 404。

- 解法：clone 的是 https://github.com/codejunkie99/Serein-Bot.git。

<!-- lang:en -->

A typo in the clone URL

- Problem: The Serein-Bot README and the build-from-source doc tell you to clone codejunkie99/SereinBot. That URL 404s.

- Solution: Clone https://github.com/codejunkie99/Serein-Bot.git.

<!-- /bilingual:section -->

<!-- bilingual:section -->

<!-- lang:zh -->

不写交接笔记就压缩（Compacting without a Handoff Note）

- 问题：下一个 harness 会丢掉精确 ID 和悬空事项。

- 解法：任何压缩或交接之前，先跑 python3 scripts/recap.py（或者把模板填好）。

<!-- lang:en -->

Compacting without a Handoff Note

- Problem: The next harness loses exact IDs and open loops.

- Solution: Run python3 scripts/recap.py (or fill the template) before any compact or handoff.

<!-- /bilingual:section -->

<!-- bilingual:section -->

<!-- lang:zh -->

提示词里的密钥（Secrets in the prompt）

- 问题：第二个 harness、某份日志、或者某次 recap 会把 token 复制走。

- 解法：值留在保险库里。交接时给一张通行证，只在代理里兑换。

<!-- lang:en -->

Secrets in the prompt

- Problem: A second harness, a log, or a recap copies a token.

- Solution: Keep the value in the vault. Hand over a Hall Pass. Redeem only through the proxy.

<!-- /bilingual:section -->

<!-- bilingual:section -->

<!-- lang:zh -->

桌面太吵（A noisy Desk）

- 问题：每 30 分钟一次的巡检每次都给你发消息。

- 解法：沉默规则才是产品本身。如果脚本做不到回复 NOTHING，就别装这个 cron。Anthropic 的建议是：从安静开始，慢慢挣来注意力。

<!-- lang:en -->

A noisy Desk

- Problem: A 30 minute check-in texts you every time it runs.

- Solution: The silence rule is the product. If the script cannot reply NOTHING, do not install the cron. Anthropic's advice is to start quiet and earn attention.

<!-- /bilingual:section -->

<!-- bilingual:section -->

<!-- lang:zh -->

把整个记忆仓库都加载进去（Loading the whole memory repo）

- 问题：整个笔记本（小时笔记、每周文件、原始日志）全塞进提示词，模型只会更差，不会更好。

- 解法：只加载 SOUL、USER、AUTONOMY、STATE.md 和 recap。任务真需要时，再去拉当天笔记或某个 progress 文件。

<!-- lang:en -->

Loading the whole memory repo

- Problem: The whole Notebook (hourly notes, weekly files, and the raw log) all go into the prompt. The model gets worse, not better.

- Solution: Load SOUL, USER, AUTONOMY, STATE.md, and the recap. Pull a daily note or a progress file only when the task needs it.

<!-- /bilingual:section -->

<!-- bilingual:section -->

<!-- lang:zh -->

把拆解文当源码（Treating a teardown as source code）

- 问题：这份指南里有一部分常驻助理的内部结构，来自已经公开发表的拆解，不是来自某个公开仓库。

- 解法：把它们当架构参考。不要声称你复现了未公开的提示词、评测或语音配置。

<!-- lang:en -->

Treating a teardown as source code

- Problem: Some always-on assistant internals in this guide come from published teardowns, not from a public repo.

- Solution: Use them as architecture. Do not claim you reproduced unpublished prompts, evals, or voice setup.

## 如果重来我会怎么做 / Things I would do differently

<!-- bilingual:section -->

<!-- lang:zh -->

- 第一天就把交接笔记的格式定下来，在 Claude Code 和 Codex 开始接力之前。交接本身就是产品。

- 从一开始就把身份文件和任务状态分开。混在一起，家规迟早会被归档掉。

- 用 Serein 当那个 Mac 应用，而不是从头重建审批、保险库和浏览器。

- 巡检的起点，比你想要的更安静一点。间隔随时可以缩短，注意力却很难挣回来。

- 对通行证要诚实。把范式交出去，但不要假装它是一个托管的云端浏览器系统。

<!-- lang:en -->

- Write the Handoff Note format on day one, before any chaining of Claude Code and Codex. The handoff is the product.

- Keep identity files separate from task state from the start. Mixing them is how house rules get archived.

- Use Serein as the Mac app instead of rebuilding approvals, a vault, and a browser from scratch.

- Start the Round quieter than you think you want. You can always shorten the interval. It is harder to win back attention.

- Be honest about the Hall Pass. Ship the pattern. Do not pretend it is a hosted cloud-browser system.

## 结语 / Conclusion

<!-- bilingual:section -->

<!-- lang:zh -->

私人助理不是一个界面更漂亮的模型。

它是一整套栈：托盘、闹钟、笔记本、旋钮和桌面，围着一个你随时能换掉的模型。模型大部分时间应该睡着。醒来的时候，它应该已经知道自己是谁、有什么在悬着、被允许做什么，以及这件事需不需要你知道。

Serein 是那个 Mac 应用。pa-guide-build 里的文件才是你能带走的部分。把那些文件握在自己手里，放进 git，教链上每一个 agent 去读它们。

模型可以在更好的出来时换掉。笔记本、交接笔记、旋钮和沉默规则，是你以后租不回来的东西。

<!-- lang:en -->

A personal assistant is not a model with a nicer chat box.

It is a stack: a Tray, Alarms, a Notebook, a Dial, and a Desk, wrapped around a model you can swap. The model should spend most of its time asleep. When it wakes, it should already know who it is, what is open, what it is allowed to do, and whether you need to hear about it.

Serein is the Mac app. The files in pa-guide-build are the part you can take with you. Own those files. Keep them in git. Teach every agent in the chain to read them.

The model you can change when something better ships. The Notebook, the Handoff Note, the Dial, and the silence rule you cannot rent back later.
