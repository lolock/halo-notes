> Datadog 让 Agent 为确定性内核编写规范，再由内核生成应用代码。

## Agent、机械化与工业化 / Agents, mechanization, and industrialization

Datadog 的所有工程师都在生产代码中使用 AI 编码工具，而 Claude Code 驱动了其中至少三分之二。借助 Claude Code，他们在 SDLC 中生成了四种不同类别的个性化流程：

- **针对性变更**：数十个棘手的 bug 修复、性能优化以及到现有服务的桥接
- **大型重构**：三天内重构一个自定义 protobuf 解析器，以及在三个月内将监控指标从 FoundationDB 重写为 Postgres
- **替换大型组件**：新的分片算法和自动扩缩容重新设计
- **构建完整系统**：用 Postgres 替换 MongoDB、BYOC 控制平面以及从零搭建的摄取管道

然而，随着工作流经这张地图，他们发现在一个维度上生成变得更加复杂，在另一个维度上验证变得更加模糊。

对于工程师来说，"流畅"过去意味着意图和代码之间的直接关系。你理解问题、编写代码、测试、审查、发布、运维、重复。有了 Agent，这种抽象正在快速变化。

"你不再编写代码，你在塑造工作。你决定 Agent 应该看到什么、它应该拥有什么工具、成功的定义是什么、失败应该如何被检测……这就像每个人都升职了三级进入了管理层——而他们并没有为此签约，因为他们是工程师，"Datadog 工程副总裁 Sesh Nalla 说。

借助 Claude Managed Agents 等方法，Datadog 的会话运行得更长，有时持续数天。每个 Agent 都会发明自己的工具、自己的胶水代码和自己的约定。Agent 变得明显更有用，但需要人类来弥合 Agent 执行和为人类设计的工具之间的鸿沟。

## 流程问题 / The flow problem

机械工具（machine tools）是你在制造业中看到的夹具、量具和铣床。它们生产精确、可重复的零件，然后组装成更大、更复杂的机器——如发动机、飞机、核反应堆和登月舱。它们是工业化的突破，因为零件变得可组合、可检查和可替换。

Temper 就是 Sesh 所说的 Datadog 对 Agent 系统"万能机械工具"的尝试。换句话说，是 Agent 以安全和精确的方式构建所需的最小内核。

"这就是我觉得需要更结构化东西的节点，"Sesh 说。"如果 Agent 要构建和运维我们系统的大部分——我们的数据库，那些是关键任务——它们需要等同于这个机械工具概念的东西。Temper 就是 Datadog 的机械工具。"

## 通往 Temper 之路 / The road to Temper

机械化意味着 Agent 现在在做更多的工作。工业化意味着工作变得可重复、可验证、可控和可扩展。在 Datadog，这并非一蹴而就：通往 Temper 的道路经过了另外三个项目——Courier、BitsEvolve 和 Helix。每个项目都暴露了下一个的瓶颈，并使他们能够扩大雄心。

2024 年，他们推出了 Courier，一个分布式队列系统。他们从头开始完全手工构建，花了一年时间。

"难点不在于构建零件，而在于让它们之间的交互可观察、可测试和可验证，"Sesh 说。"所以我们对形式化建模和模拟非常严格……找出了那些错误代价高昂或难以逆转的部分，并在那里提高了严谨性。"

2025 年 9 月，他们构建了 BitsEvolve，一个闭环进化优化框架。一个模型委员会生成代码变体。一连串的基准测试、测试和生产可观测性决定了哪些变体能存活。

"这是我第一次瞥见软件的某些部分可以像活生物体一样被培育——通过变异、反馈和适应来成长，"Sesh 说。

问题是：进化的质量只取决于其适应的环境，而 BitsEvolve 的瓶颈就是反馈循环。于是他们构建了 Helix，一个可与 Kafka 媲美的流式服务。Claude Code 完成了大部分构建工作，由一个人引导。

"令我们难以置信的是，在几天内我们就拥有了一个功能完整的、可与 Kafka 媲美的系统，"Sesh 说。"（构建速度很快）我们开始对其进行影子测试，发现它的成本可以降低 2 到 5 倍。"

然而，让它上线花费了更多的里程：运维加固只能随着时间的推移并由多于一个人来完成，这仍在推广过程中。

"瓶颈再次移动了——Agent 可以构建系统的大部分……但人类仍然需要协调，通过为人类设计的工具和机制将工作交付到生产环境，"Sesh 说。

Datadog 需要一种方式，让 Agent 在可验证的、受策略驱动的运行时环境中构建自己的工具。这个运行时就是 Temper。

## Temper / Temper

Agent 生产代码的速度比任何团队手动审查的速度都快，但它们会犯错误。对 Sesh 来说，Agent 生成的内容与通过验证的内容之间的差距，就是失败模式的聚集地。然而，简单地在传统代码库上包裹一个 Agent，只是将其视为吞吐量问题，而没有缩小验证差距本身。

Temper 反转了这个等式：Agent 不生成应用代码，而是生成规范（specifications）。内核读取每个规范，通过四层分析进行验证，然后部署规范所描述的运行系统。由于规范既是经过验证的工件又是被执行的工件，因此经过验证的内容与正在运行的内容之间没有偏差。

"Temper 改变了系统的中心。Agent 不再需要为每个局部需求发明不连贯的工具。相反，它产生精确的描述——作为意图和问题领域的规范。它就像夹具或数控机床，你给它们关于你的螺纹规格的描述。它是极其可重复的。你可以运行它们，然后你可以用它们建造飞机和复杂的东西，"Sesh 说。

因此在这里，Agent 不再每次都即兴发明最终的机制。它可以产生精确的描述，并通过 Temper（或类似 Temper 的机制）进行迭代，先让某样东西工作，然后将其转变为可重复、可检查和可重用的东西，这样你就可以围绕你的代码库建立一个软件工厂。

每个能力由三个契约描述：

- **行为**：状态、转换、前置条件以及必须成立的安全属性
- **数据契约**：实体类型、它们的属性以及每种类型支持的操作，以机器可解析的形式发布，使 Agent 无需文档即可发现完整 API
- **授权**：默认拒绝、基于范围的审批，拒绝记录为待处理决策，人类可以批准并热加载到策略引擎中

每个规范在加载前要经过四个独立的验证层。符号推理证明每个守卫是可满足的、每个不变量是归纳的。穷举状态探索访问每个可达状态。

确定性模拟运行实际的生产代码路径，带有注入的故障——丢包、延迟、重排序、崩溃——因此故障在相同种子下可精确重现。

随机化属性测试运行约一千个伪随机操作序列，并将任何违反行为缩小到最小反例。对于小型规范，整个级联在远不到一秒内完成。

## Helix 的暗工厂 / The dark factory for Helix

Simon Willison 推广了"暗工厂"（dark factory）这个术语，指 Agent 在没有人类在场的情况下持续工作的软件流程。在 Helix 的暗工厂中，Temper 扮演三个角色。

它是 Agent 控制平面——管理会话、角色、工作队列和生命周期。它是工具构建层，让 Agent 使用小型 Temper 应用桥接 SDLC 工具（Git、CI、部署）。它还是 Helix 控制 API——数据平面周围的生命周期接口。

"令人惊讶的是，它开始感觉比 Agent 基础设施更通用。很多软件，如果你眯眼来看，就是数据库 API 周围的控制逻辑：状态、围绕变更的策略、生命周期转换、与外部系统的集成。Temper 在某种意义上可以是通用的——它可以应用于任何具有我所描述形状的软件，"Sesh 说。

## 为什么不直接构建 CRUD 应用？ / Why not just build a CRUD app?

"Claude Code 可以（用 TypeScript 或 Python）很好地构建 CRUD 应用。然而，在普通的 CRUD 应用中，控制逻辑分散在路由、数据库约束、服务代码、后台任务和文档中。它可能有良好的测试和覆盖率，但操作模式（通常表现为状态机）是隐含在代码库中的，"Sesh 说。

"Temper 使那个状态机显式化。Agent 产生精确的描述，而不是任意代码。编译步骤在 LLM 之外，就像你将 Rust 代码交给 Rust 编译器一样。转换表是数据，而不是隐藏在服务方法中的面条式控制流。Agent 可以动态地、安全地更改它，并热加载它，而无需经过 CI，"他解释道。

Temper 背后的理念是每个构件都应该足够小，能够装进你的脑子里。航空和金融系统等高安全性软件几十年来一直以这种方式构建，但在人类身上达到这种严谨性的成本对通用软件来说太高了——直到 Agent 进入画面。

## 未来方向 / Where this is going

工业革命之所以成为可能，是因为机械工具使零件变得可组合、可检查和可替换，从而使我们能够构建越来越大、越来越复杂的机器。

"如果 Agent 能够在这种纪律性下在工厂内自主构建软件，也许我们不需要止步于暗工厂。以这种方式构建的软件开始感觉像一个我们可以通过反馈、选择和适应来培育、培养和进化的有机体，"Sesh 说。
