# Halo Notes 编辑设计规范 · 待审样稿

状态：设计提案，尚未替换现有站点。本目录是独立审阅产物，首页与阅读页使用五篇现有文章，正文、标题和原图不改写。本次不提交、不部署。

## 1. 目标和判断顺序

主要任务是发现文章、判断是否值得读、进入连续阅读。品牌识别辅助这些任务；搜索和分类提供另一条找文路径；主题等偏好按需出现。判断顺序是：任务优先级 → 信息分组 → 视觉层级 → 样式细节。

本提案将“人文科技杂志”解释为内容突出、阅读从容、工具克制、关系清楚，而不是大刊头加大量空白。这里的像素和比例是本站的可检验设计选择，不是外部设计体系规定的通用答案。

## 2. 原则如何变成规则

| 依据 | 本站规则 | 如何检验 |
| --- | --- | --- |
| 视觉层级、尺度与对比 | 移动端主文章标题先于大图；辅助文字不与标题争夺注意力 | 去掉颜色后，仍能看出文章主次；首屏能读懂第一篇文章讲什么 |
| 接近性与分组 | 同篇标题、摘要与配图紧密关联；文章之间的间距大于标题与元信息之间的间距 | 列表中不会把前一篇配图误认作后一篇封面 |
| 网格、节奏与对齐 | 文本共用内容左边线，采用固定间距档位；桌面与手机重新组合相同的信息单元 | 不为单个按钮或单篇标题添加例外偏移 |
| 字体角色 | 刊名、文章标题、正文、辅助信息与操作分别使用规定样式 | 同一功能在所有页面呈现相同字重、字号与状态 |
| 渐进呈现 | 搜索有固定入口，点击后出现输入框；显示偏好进入菜单；阅读来源与目录按需展开 | 搜索、分类、主题均可通过键盘完成；重要功能没有被纯装饰图形代替 |
| 一致性允许功能差异 | 图片处理由信息类型决定，摄影、截图、无图文章各有规则 | 不裁掉截图中的文字，不制造空白垫高容器，不伪造无图封面 |

依据：[NN/g 视觉原则](https://www.nngroup.com/articles/principles-visual-design/)、[NN/g 渐进呈现](https://www.nngroup.com/articles/progressive-disclosure/)、[GOV.UK 设计原则](https://www.gov.uk/guidance/government-design-principles)。上述应用规则是针对本站的推导，来源不代表为具体布局背书。

## 3. 信息结构

### 首页

1. 品牌与工具：刊名、搜索入口、菜单入口，共一行。
2. 分类导航：单行短入口，超出宽度横向滚动，不增加多行刊头。
3. 主文章：分类／日期／双语标识（如适用） → 完整中文标题 → 中文摘要 → 配图。手机先读标题，桌面允许图文并列。
4. 后续列表：仅展示中文标题与中文摘要，双语文章在元信息行标注“双语”；摄影用辅助缩略图，无图文章自然采用文字布局。

首页不重复展示英文标题或英文摘要，保留中文内容中的产品名与技术术语。双语标识根据文章格式元数据显示，与分类、日期同级，不使用醒目按钮或独立信息行。完整英文内容保留在阅读页。

取消独立宣传语、列表总数、重复的“最新文章”标题和常驻搜索表单。样稿只展示五篇，因此用“已读到本组文章末尾”说明范围，不伪装成全站文章列表。

### 阅读页

刊头 → 返回列表 → 完整中英标题 → 可展开来源／目录 → 正文。普通文章不强行套双语结构；双语文章保留完整语义组，桌面分栏、手机顺序阅读。长标题不截断，英文题目不省略。来源与目录收起时共用一行辅助入口，展开后回到自然文档流，不压住移动端正文。

## 4. 字体与空间

| 角色 | 手机初始样式 | 桌面初始样式 | 用途 |
| --- | --- | --- | --- |
| 刊名 | 27px 衬线 | 30px 衬线 | 识别站点，避免压过主文章 |
| 首页主标题 | 24px / 1.45 | 36px / 1.38 | 阅读入口，完整显示 |
| 列表标题 | 20px / 1.5 | 23px / 1.45 | 可扫描的内容层级 |
| 阅读页英文题目 | 19px / 1.5 衬线 | 23px / 1.5 | 与中文题目属于同一组 |
| 阅读正文 | 18px / 1.9 衬线 | 同左 | 中文长阅读 |
| 英文正文 | 17px / 1.7 | 18px / 1.7 | 保持英文段落节奏 |
| 摘要 | 14px / 1.8 无衬线 | 15px / 1.8 | 帮助判断文章内容 |
| 元信息／操作 | 12–14px 无衬线 | 同左 | 辅助内容和交互 |
| 代码 | 13px / 1.6 等宽 | 同左 | 技术原文 |

核心间距使用 8 / 12 / 16 / 24 / 32 / 48px，分别承担微小分隔、组内关系、段落与组间关系。不是所有距离必须相等。手机内容边距20px；桌面24px边距、最大内容宽1200px。手机刊头56px，图标18px、点击区域44px。后者是本提案的易操作目标，不把图标自身尺寸与触控面积混为一谈。

从 [Carbon 的字体策略](https://carbondesignsystem.com/elements/typography/style-strategies/)借鉴“按任务区分阅读表达与操作字体角色”，从[网格原理](https://carbondesignsystem.com/elements/2x-grid/overview/)借鉴统一尺度与对齐线；不照搬其字体、列数或组件外观。

## 5. 图片规则

| 图片用途 | 样稿处理 | 原因与边界 |
| --- | --- | --- |
| 带字截图、流程图 | 按原始比例完整展示；高度随图宽计算 | 信息保真优先。首篇原图约2.5:1，不再放进3:2容器加空白 |
| 主视觉摄影 | 16:9 是本样稿的候选展示比例 | 建立可控视觉重心；需逐图确认主体与人脸未被裁掉，不能作为全库默认批处理 |
| 列表摄影缩略图 | 4:3 辅助缩略图 | 与标题共同构成紧凑条目。若细节无法在缩略图中辨认，应采用文字条目或进入文章查看 |
| 无图文章 | 纯排版条目，不生成装饰性假封面 | 让标题本身承担信息表达，避免标题重复出现两次 |
| 正文原图 | 原图比例、完整显示 | 配图承担解释作用，不受封面规则约束 |

本样稿使用的摄影来自现有 Hackathon 文章；默认居中裁切仅用于审阅，必须结合截图判断。所有正文配图保留原始内容。图片素材以原文件嵌入，样稿约17MB，不能作为未来生产页面的体积预算。

## 6. 颜色与交互

暖白 `#f6f3eb` / 墨色 `#272a24` / 辅助色 `#65685e` / 朱砂 `#94482f`；深色 `#22251f` / 文本 `#eeeade` / 辅助 `#b9bbae` / 强调 `#e6aa8f`。强调色用于选中与交互，不为每个栏目增加竞争色。

普通文本目标对比度至少4.5:1，按[WCAG 2.2 对比度说明](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)核对。对比度通过不等于整站无障碍合规。

菜单使用原生对话框，支持 Escape 和焦点返回。搜索保留可访问名称；主题状态使用 aria-pressed。所有可操作元素有可见键盘焦点。深色模式与灰度样稿分别检验配色及层级，不用降低正文对比度表达“高级感”。

## 7. 样稿验收标准

- 在390×844视口，首次打开时搜索和菜单关闭；主文章完整标题、摘要与配图均可进入首屏。长标题不靠行数截断完成目标。
- 同样内容下，记录标题开始位置、图片高度、下一条标题位置，与现有页面的实测结果对照；不能用“缩小所有字体”换取数字。
- 390px与1440px无页面横向溢出，双语阅读栏按宽度重组。
- 放大文字后内容可以自然变高，不覆盖或截断。放大验收不要求仍满足默认字号的首屏高度目标。
- 真实搜索、空结果恢复、分类、菜单、深色模式、文章目录可用；所有样稿文章均有完整阅读页。
- 截图、照片和无图条目各单独检查，正文与源文章的文本和资源必须保留。
- 所有原图和正文嵌入HTML，断网打开可阅览；外部原文链接仍需要网络。

这些是当前提案的验收条件，尚未做真实用户任务测试，也不声称完成iPhone实机验收。
