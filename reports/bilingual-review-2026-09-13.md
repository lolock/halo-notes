# 中英双语文章检查（2026-09-13）

范围：从索引标题或标签识别的 93 篇双语候选，进行结构扫描并抽查具体译义。未逐篇对照外部原文，不能将本报告当作全部译文准确性或全文完整性认证。本次只审查双语内容，未批量重译、重排或修改正文。

## 1. 两篇标为双语，实际缺少英文正文

这两篇索引均含 `双语翻译` 标签，也有中英双语标题，但正文是中文，英文只出现在标题、小标题或术语中，不满足保留英文全文的要求：

- [Anthropic 如何保护其 AI 原生软件开发生命周期](../articles/anthropic-secures-ai-native-sdlc.md)
- [Datadog 如何为 Claude Code 构建“万能机械工具”](../articles/datadog-universal-machine-tool-claude-code.md)

应优先从原网页或可信源快照恢复英文，按段落与现有译文对齐；不能从中文反向翻译出所谓“原文”。

## 2. 抽查确认的译义问题

| 文章 | 当前译法 | 问题与建议 |
| --- | --- | --- |

## 3. 结构与阅读问题

- 93 篇候选中，6 篇正文包含多个顶层 `#` 标题（扫描排除 fenced code）。部分是重复文章标题与元信息，部分是中英标题分别占一级标题，应逐篇区分。
- 6 篇分别为 Datadog、Rakuten、Base44、Linear 技术拆解、Managed Agents 自托管沙盒、The Claude-Native Designer。
- 存在 `> EN:` / `> ZH:`、`> **EN:**` + 中文正文、普通 `ZH：`、整篇不标语言的交替段落等形式；15 篇同时出现多种标记形式，16 篇没有这些显式语言标记。这些统计只说明格式分布，不能单独证明漏译。
- 有些标题中文在前，有些英文在前；引用块既用于英文原文又用于真正引用，视觉含义混在一起。对手机长文尤其不利。
- 阅读器目前原样渲染 Markdown，没有可靠的语义段落对，也没有“中文主读/中英对照”模式。不能仅凭是否含汉字就自动隐藏段落，否则会隐藏代码说明、混合术语或遗漏列表。
- 历史 `scripts/refine_bilingual_reading.py` 只认识有限格式，主要是 `> **EN:**`，不能作为全站双语修复工具；它合并短段落也不能验证源文完整性。

## 4. 不应把标签计数差异当作漏译

Computer use 一文的引用中有 9 个 EN、10 个 ZH，其中一段英文分别介绍 Skills API 与 Files API，译文拆为两个中文段落，内容对应。因此“一段英文必须严格等于一个中文标签”的规则会误报。

可靠检查需要源段落 ID/顺序及输出段落映射，允许一对多，并分别覆盖列表、表格、代码、图片和链接。仅有全文字数或 EN/ZH 计数不够。

## 建议优先级

1. 补齐两篇缺少的英文原文，修正已确认的译义错误。
2. 清理重复标题与元信息，保留代码和真实引用结构。
3. 统一为可识别的段落对，再提供中文主读与中英对照；长文避免一次性混排两种语言。
4. 将结构及来源保留检查接入发布过程，人工/模型语义审校与机械完整性检查分开报告。
