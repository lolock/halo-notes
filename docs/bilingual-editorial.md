# 双语编辑与杂志阅读规范

用户要求：专业的杂志式中英双语阅读，能连续读完一个论点；不要一句中文一句英文，也不要为只有几个词的短行单独创建翻译分隔块。

## 编辑单位

以原文的完整段落、自然小节或同一论点的连续段落为单位。先读懂上下文，再组织中文。网页换行、DraftJS block、抓取器输出行数都不等于编辑段落。属于同一论点的短句可放进同一组，保留作者有意的强调和段落节奏；不得按句号、固定词数或固定句数机械拆分/合并。

每组先放连续的中文，再放对应的连续英文。英文保留原文措辞与顺序，中文允许一对多、多对一，只要信息完整、对应明确。中文要作为独立文章自然可读，准确处理术语和句间关系，不模仿英文碎句，不添加原文没有的观点。

小节标题在 Markdown 的 `bilingual:section` 标记之外，只出现一次，使用 `## 中文标题 / English heading`。全文只有一个一级标题。图片、代码、表格和视频海报留在原来的内容边界；不为了凑长段跨过它们。完整列表各语言各呈现一次，不按列表项切换语言。真正的引语使用引用块，普通英文不能套引用块。

手机按组阅读中文、再读同组英文；桌面宽屏按组分栏，各栏自然排版，不逐行对齐、不补空白撑齐高度。语言提示只在组首出现。

## 翻译对应与视觉分组

`bilingual:section` 定义翻译对应单元（BilingualSection），不承诺一个独立视觉块。阅读器先解析有序文档流（翻译单元与共享 block），再由 `groupSections` 生成 DisplayGroup，最后由 `renderGroups` 输出页面。`render` 仍返回原有的 `sections` 和 `issues`，供发布校验和旧调用方使用。

连续的普通段落、完整列表可以在展示层合组；短引导段优先开始下一组，总结段跟随上一组并结束该论点。明确的警告、整段加粗强调、真实引用和混合结构小节保守保留。任一语言中出现代码、媒体、表格、引用、标题或 HTML 结构都阻止普通合组，包括列表或链接中的嵌套结构。不得按中英 token 下标拆分配对，也不改写 Markdown 段落。

标题默认阻断合组。唯一例外是短引导段紧接 H2/H3、随后为以正文开始的双语内容：三者可以组成一个视觉组，按“引导双语栏 → 共享标题 → 主体双语栏”的原顺序呈现。标题仍在语言栏外，只出现一次，保留 TOC、anchor 和译名。组首保留语言提示。

代码、图片两侧的短说明不跨结构合并，通过紧凑提示、栏间距与相邻边距建立视觉连续性。受真实边界限制的短单元允许独立存在；不以 spread 数量减少作为验收标准。自动合组仅在结构允许时使用长度上限（850 个中文栏非空白字符、360 个英文词、每语言累计最多 8 个顶层 block），避免连续短段无限累积；原作者已定义的单个长 section 不被拆分。旧格式继续使用原有兼容分组，不再二次合并。

当前没有 `display:join-next` / `display:break` 语法；同名字串、注释和代码示例仍按普通 Markdown 处理。保留各语言内部顺序、共享结构位置和每个翻译单元引用，为后续阅读模式提供数据边界，本轮不实现模式切换。

## Markdown 格式：magazine-v1

新英文文章的 entry.json 增加 `source_language: "en"` 和 `bilingual_format: "magazine-v1"`。现有索引必需字段继续保留。

```markdown
## 从设计到交付 / From design to delivery

<!-- bilingual:section -->

<!-- lang:zh -->

这里是完整中文段落。同一个论点中的短句在此自然衔接。

这是同一小节的下一段，可以有链接、强调或完整列表。

<!-- lang:en -->

The complete original paragraph goes here. Preserve the author's wording.

The next original paragraph belongs to the same section.

<!-- /bilingual:section -->

![原图说明](/halo-notes/articles/assets/example/figure.jpg)
```

标记独占一行，并用空行与正文分开。每组必须依次包含开始、zh、en、结束标记；不要嵌套。不要在正文输出 `EN:`、`ZH:`、翻译过程说明。代码块中的标记只是代码，不是分组指令。新格式无需依赖阅读器猜测语言。

## 完整性验收与排版验收分开

- 私有草稿中保留源快照。给源段落/列表/引语保留稳定 ID，在 `manifest.json` 记录每个编辑小节对应的源 ID 顺序；允许多段源文组成一个小节。
- 按顺序核对全部英文原文、译文信息、链接、代码和媒体。不以 EN/ZH 标签数量或中英段落数量相同作为完整性证据。
- 运行 `node scripts/check_bilingual.cjs --bundle <目录>`。发布入口自动执行该检查，缺少新格式或小节语言不全会拒绝发布。结构通过不代表译义已核验。
- 打开真实阅读页，在宽屏和手机上各检查一遍：短句没有反复语言切换；同一论点连续；列表完整；真正的引语仍可识别；没有横向溢出。

旧文章的明确 EN/ZH 标记以及双语标题下的相邻语言段落由阅读器兼容分组；在标题、图片、代码、表格、引语和分隔线处停止。对于没有小节的旧长文，只在完整语言对之间设置长度上限，避免手机端两种语言相距过远。兼容分组是展示修复，不是译文完整性认证，也不能替代人工编辑；缺少原文或结构含糊的文章保持可见，逐篇核对后迁移。

旧 `refine_bilingual_reading.py` 按字符数合并段落，已停用。不要用字符阈值批量改写现有文章。维护者修订正文时采用显式小节并逐篇核对。
